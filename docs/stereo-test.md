# 开黑版和娱乐版声道切换：本机测试记录

2026-11-07，v1.0.3 本机验证记录。

## 使用

- 新增“设为单声道”“设为双声道”，分别切换当前所选版本的声道，保留当时的码率和编码格式。
- 本次适配经过完整文件指纹及加载代码校验的开黑版 ZEGO 3.25.0.52035、娱乐版 3.25.0.52036。其他引擎仍可按原有范围使用码率功能，声道切换会拒绝执行。
- 进入所选版本的房间并上麦后再操作。设为双声道后，本机会同时检查采集声道、编码配置和正在工作的编码器声道，不能仅靠 SDK 配置回读判断成功。
- 声卡必须向 TT 提供左右不同的输入，才有真正的立体声效果。一个麦克风复制成左右两路不会产生新的空间信息。
- “自动保持”仍只保持码率。重新进房或 TT 自己重设声音配置后，可读取配置并重新切换声道。
- 关闭工具不会自动撤销已成功应用的声道。需要恢复时点击“设为单声道”。
- 设置失败会尝试恢复原编码配置和原采集模式。响应超时或恢复未完成时不继续调用，并提示重启 TT。

## 已验证

测试客户端 TT 1.23.0.1，进程 TTVoice.exe，引擎 3.25.0.52035。

1. 测试前主路为 192 kbps、单声道、编码 ID 6，采集模式为单声道。
2. 调用 SDK 双声道采集接口和音频配置接口后，采集引擎声道与底层编码器声道均为 2，码率仍为 192，编码 ID 仍为 6。
3. 恢复后，配置、采集模式和采集声道恢复到原值。
4. 新增功能的命令行集成测试和实际 GUI 的两个按钮均完成切换、验证及恢复。
5. 既有码率功能在 modern64、legacy64、legacy32 模拟目标上完成读取、设置、回读、越界拒绝；这些模拟目标也验证了未适配引擎的声道请求不会改动原配置。
6. 实时码率采样单元测试、实际 DLL 的 ABI/加载代码检查，以及声道调用参数测试通过。

随后补测娱乐版 TT 2.30.5，引擎 3.25.0.52036：

1. 测试前为 48 kbps、单声道编码；采集已经是双声道。底层正在工作的编码器采样率为 48000 Hz。
2. 在保留编码格式的情况下验证了双声道切换，再设置 192 kbps。实际编码器的声道为 2、采样率为 48000 Hz、码率为 192000 bps，实时发送约 200–203 kbps。
3. 切回单声道通过；测试结束后恢复了原始编码配置和独立的双声道采集模式。
4. GUI 娱乐版入口和双声道按钮实测通过。
5. 开黑版再次上麦后，直接读到实际编码器也是 48000 Hz、双声道、192000 bps。

采样率从实际编码器对象读取，并对照初始化代码核对字段含义。上层编码配置中另有 44100 的请求值，它不代表当前 Low3 编码器真正采用的采样率。

这些是本机参数和处理链验证，不是远端立体声或听感验收。两版当前编码器均已确认使用 48 kHz，本次没有修改采样率，也未宣称已经完成 48 kHz 端到端传输验收。

## 尚需对端试听

使用两台设备，接收端戴耳机；让声卡输入“仅左声道”和“仅右声道”的合成测试音，确认另一端能分别在左右耳听到，并比较伴奏和混响。不能用“界面显示双声道”或“码率曲线升高”替代这一测试。

## 构建与检查

Windows 上使用 MinGW-w64 兼容编译器；本次使用项目 build/toolchain 内的便携 LLVM-MinGW 20261104，不改系统 PATH。

```powershell
x86_64-w64-mingw32-windres resources/app.rc -O coff -o build/stereo/icon.o
x86_64-w64-mingw32-gcc -std=c11 -Wall -Wextra -Werror -O2 -municode -mwindows src/ui.c src/controller.c src/telemetry.c src/telemetry_core.c src/locator.c src/target.c build/stereo/icon.o -ladvapi32 -lcomdlg32 -lshell32 -lole32 -luuid -lm -o "build/stereo/克克咪 TT语音增强.exe"
```

控制器新增了 SHA-256 校验，编译单独的控制器测试程序时也需要链接 `-ladvapi32`。

`tests/stereo_feature_test.py` 只在用户明确授权真实客户端测试时运行；它会短暂切换声道，并在正常测试路径中恢复原声道。`tests/stereo_live_probe.c` 为同一版本引擎的独立短时实验程序，包含原配置及采集模式的恢复。不要把这些测试程序当作日常工具。

`tests/entertainment_stereo_test.c` 是娱乐版双声道、192 kbps 和单声道的短时集成测试，会恢复原配置及原采集模式；必须显式传入 `--exercise-and-restore`。`tests/stereo_state_probe.c` 只读检查两个正在发送音频的客户端，核验指纹、采集声道、实际编码器声道、工作采样率及码率。
